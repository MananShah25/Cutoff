| D-004 | 2026-10-10 | The RV32I configuration of PicoRV32 lives in our wrapper `rtl/cutoff_core.v`; `rtl/picorv32/picorv32.v` is the unmodified submodule, pinned at `ef203c2` (2026-09-07). | D-005 | 2026-10-10 | Memory map for the testbench: 64 KiB flat RAM at address 0 (the core's reset address); a store to `0x1000_0000` ends the program and its data word is the exit code; any other access outside RAM is reported as a memory fault; default cycle limit 100,000. The memory slave answers every transfer after one wait cycle (about two cycles per transfer). | Spec section 7 leaves exact values to us. Must be mirrored by the reference model in Step 2. |
| D-006 | 2026-10-10 | `cutoff doctor` requires at least 5 GiB of free disk where it is run; a missing CMake is only a warning. | Result folders and pools grow in later steps; CMake is only needed to rebuild. |
| D-007 | 2026-10-10 | Initial state is pinned at compile time (`--x-initial 0 --x-assign 0`) and by `REGS_INIT_ZERO=1`. | Determinism (spec rule 4); proven by test V-05. |
| D-008 | 2026-10-10 | `-Wall -Wextra` apply to Cutoff's own sources only, not to Verilator's generated model or GoogleTest. | The generated code is third-party. Our code must stay warning-free under all three configurations. |
| D-009 | 2026-10-10 | The CI workflow is written but has not been run on GitHub (there is no remote). | Spec lists CI with sanitizers; it cannot be validated locally. Treat as untested until a remote exists. |
| D-010 | 2026-10-10 | Reference-model semantics (full list at the top of `model/model.hpp`): all registers and RAM start at zero; control-flow targets must be 4-byte aligned (taken branch, JAL, JALR trap otherwise; not-taken branches never trap); misaligned LH/LHU/SH/LW/SW trap and byte accesses never do, alignment is checked before range; a store to the magic word ends the run with the bus data word as exit code (SB and SH replicate into all lanes/both halves); other out-of-RAM accesses and fetches are MemFault; FENCE is a no-op; ECALL, EBREAK, CSR, M/C-extension and FENCE.I words trap. On Trap or MemFault the register file is unspecified and must not be compared. | Spec section 7 rules, with each point checked against the pinned core (verification log V-11 to V-15). |
| D-011 | 2026-10-10 | The Verilated testbench no longer ends a run at the instant it sees a bus event (magic store or out-of-range access). It keeps clocking for `trap_settle_cycles` (default 4) and reports Trap if the core traps meanwhile. After a bus event the testbench stops answering the core, so there is no upper bound on this window. | Fixes a bug in my Step 1 harness, found by the Step 2 differential tests (V-12). |
| D-012 | 2026-10-10 | The instruction decoder and encoder live in `model/` (`rv32i.hpp`) and are shared by the future generator. The encoder aborts on any out-of-range immediate, in release builds too. Sign extension and arithmetic shift are written with unsigned operations (`model/bits.hpp`). | One ISA definition for model, generator and tests; a bad encoding must never be silent. |
| D-013 | 2026-10-10 | The model's retire and store trace shapes (`RetireRecord`, `StoreRecord`) are provisional. Step 8 may change them when checkers C2 and C3 are built against the real bus tap and RVFI. | The exact fields depend on what RVFI exposes (V-03). |
| D-014 | 2026-10-10 | `scripts/tidy.sh` only analyses git-tracked files, and `.clang-tidy` ignores positive integer literals in `bugprone-signed-bitwise`. New files must be `git add`-ed before tidy sees them. | Keeps third-party and generated code out; the literal option removes noise from shift counts such as `x >> 7`. |
| D-015 | 2026-10-10 | Profile G0 (uniform), generator version 1. Opcodes: 38, drawn uniformly (LUI, AUIPC, JAL, JALR, 6 branches, 5 loads, 3 stores, 9 register-immediate, 10 register-register, FENCE with its canonical encoding). Registers and immediates uniform: rd/rs1/rs2 over x0..x30, 12-bit immediates over the full signed range, shift amounts 0..31, 20-bit upper immediates. Layout: 62-word init block (x1..x30 random 32-bit values, x31 = data base register), body of L words (L uniform in [32, 128] by default), 3-word epilogue (`li x31, magic; sw x1, 0(x31)`), so the exit code is the final x1. | Spec section 7 profile table and program structure; FENCE kept because the core executes it as a no-op (V-15). |
| D-016 | 2026-10-10 | Safety by construction: loads/stores use x31 (never written after init) plus an immediate, giving a 4 KiB window at `0x8000..0x8fff` and only aligned accesses; code must stay below `0x8000`, so programs cannot modify themselves. Branches and JAL go strictly forward to a slot within `max_skip` (default 8) ahead, or the nearest legal slot beyond. JALR is always emitted as `auipc rb, 0; jalr rd, rb, off` with `off` landing on a forward slot and a random odd bit that JALR must clear. No jump may target the JALR half of a pair or anything past the epilogue start. | Guarantees termination and valid targets without simulating the program (spec section 7 invariants). |
| D-017 | 2026-10-10 | Randomness: SplitMix64 seeds xoshiro256**; bounded draws use Lemire's unbiased method on 32-bit words; no `std::` distributions. `program_seed(campaign_seed, index)` is stateless random access into the seed space. `kGeneratorVersion` must be bumped for any change to the (config, seed) to program mapping, and the golden hashes in `tests/gen_test.cpp` re-pinned deliberately. | Standard-library distributions differ between platforms, which would make a seed mean different programs on different machines. |
| D-018 | 2026-10-10 | Known G0 limits, kept on purpose: no backward branches (so no loops); data memory starts as zeros, so loads read 0 until a store hits the same address; boundary operand values (0, 1, -1, INT_MIN, INT_MAX) occur only by chance. | Spec: G0 is the uniform baseline; boundary bias is G2 (Step 8). These limits are what the Step 10-11 benchmark is meant to expose, not hide. |
| D-019 | 2026-10-10 | Process model: the orchestrator `fork()`s one worker per slot (no exec), talks to each over a pair of pipes with fixed-size binary messages, keeps up to two batches (default 64 programs) outstanding per worker, and passes records through `OrderedDelivery`, which releases them strictly as ids 0, 1, 2, ... It rejects duplicate or stale ids. A worker that dies mid-run stops the campaign with exit code 3 and a message naming the worker and its exit status. Ctrl-C is not handled: it ends the run and leaves a results folder without `summary.json` (resume arrives with Step 5). | Spec section 6 "one process per worker over pipes; results re-ordered by program id so a campaign is identical whatever the worker scheduling". |
| D-020 | 2026-10-10 | Checker C1 compares status, exit code, registers x1..x31 and the 64 KiB memory hash. Verdict precedence: GeneratorFault (model did not exit cleanly) > Hang (core hit its cycle limit; its own class, per spec) > StatusMismatch > ExitCodeMismatch > RegMismatch (lowest differing register) > MemMismatch. `max_cycles` default 200,000 (mean program needs about 592). | Spec sections 7 and 11. A GeneratorFault says nothing about the core, so it must not be mistaken for a core bug. |
| D-021 | 2026-10-10 | `results/<run-id>/` holds `config.toml` (full resolved settings), `events.bin`, `summary.json`, `failures/program-<id>/{failure.txt,program.hex}`. `events.bin` v1: 40-byte header, then 72-byte little-endian records with no wall-clock fields, so it is byte-identical for any worker count. `summary.json` is marked `cutoff-summary-provisional-1`; the final schema is Step 9's. All timing lives in its `timing` object. The default run id contains the UTC time, so folder names are not part of the results. | Spec section 6. Keeps determinism checkable with `cmp`. |
| D-022 | 2026-10-10 | `cutoff run` exit codes for now: 0 = all programs ran, no failure; 1 = at least one failure; 3 = setup or environment error (including a dead worker). Code 2 (budget ended before the risk threshold) arrives with the stop rule in Step 5; until then a fixed-count run that finishes cleanly returns 0. | Provisional use of spec section 5 codes; revisit in Step 5. |
| D-023 | 2026-10-10 | `cutoff.toml` is a small TOML subset (sections, strings, integers, floats, bools, comments). Unknown keys are errors that list the valid ones; command-line options override the file through the same validated settings table. `debug.corrupt_core_every` and `debug.crash_worker_at` are test hooks that fake a core bug and a worker crash; they are off by default and recorded in `config.toml` if used. | Spec section 5: one config file, resolved copy in each results folder. |
| D-024 | 2026-10-10 | Baseline gate procedure: `scripts/baseline_gate.sh` (refuses to run on a dirty tree) runs 100,000 programs, seed 1, once with 1 and once with 8 workers, and compares `events.bin`. Result files (summaries, configs, hashes; not the event streams) are archived in `docs/baselines/step4/`. | Spec rule 1: figures come from stored script output with commit and environment. |
