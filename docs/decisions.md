| D-015 | 2026-10-10 | Profile G0 (uniform), generator version 1. Opcodes: 38, drawn uniformly (LUI, AUIPC, JAL, JALR, 6 branches, 5 loads, 3 stores, 9 register-immediate, 10 register-register, FENCE with its canonical encoding). Registers and immediates uniform: rd/rs1/rs2 over x0..x30, 12-bit immediates over the full signed range, shift amounts 0..31, 20-bit upper immediates. Layout: 62-word init block (x1..x30 random 32-bit values, x31 = data base register), body of L words (L uniform in [32, 128] by default), 3-word epilogue (`li x31, magic; sw x1, 0(x31)`), so the exit code is the final x1. | Spec section 7 profile table and program structure; FENCE kept because the core executes it as a no-op (V-15). |
| D-016 | 2026-10-10 | Safety by construction: loads/stores use x31 (never written after init) plus an immediate, giving a 4 KiB window at `0x8000..0x8fff` and only aligned accesses; code must stay below `0x8000`, so programs cannot modify themselves. Branches and JAL go strictly forward to a slot within `max_skip` (default 8) ahead, or the nearest legal slot beyond. JALR is always emitted as `auipc rb, 0; jalr rd, rb, off` with `off` landing on a forward slot and a random odd bit that JALR must clear. No jump may target the JALR half of a pair or anything past the epilogue start. | Guarantees termination and valid targets without simulating the program (spec section 7 invariants). |
| D-017 | 2026-10-10 | Randomness: SplitMix64 seeds xoshiro256**; bounded draws use Lemire's unbiased method on 32-bit words; no `std::` distributions. `program_seed(campaign_seed, index)` is stateless random access into the seed space. `kGeneratorVersion` must be bumped for any change to the (config, seed) to program mapping, and the golden hashes in `tests/gen_test.cpp` re-pinned deliberately. | Standard-library distributions differ between platforms, which would make a seed mean different programs on different machines. |
| D-018 | 2026-10-10 | Known G0 limits, kept on purpose: no backward branches (so no loops); data memory starts as zeros, so loads read 0 until a store hits the same address; boundary operand values (0, 1, -1, INT_MIN, INT_MAX) occur only by chance. | Spec: G0 is the uniform baseline; boundary bias is G2 (Step 8). | D-019 | 2026-10-10 | Process model: the orchestrator `fork()`s one worker per slot (no exec), talks to each over a pair of pipes with fixed-size binary messages, keeps up to two batches (default 64 programs) outstanding per worker, and passes records through `OrderedDelivery`, which releases them strictly as ids 0, 1, 2, ... It rejects duplicate or stale ids. A worker that dies mid-run stops the campaign with exit code 3 and a message naming the worker and its exit status. Ctrl-C is not handled: it ends the run and leaves a results folder without `summary.json` (resume arrives with Step 5). | Spec section 6 "one process per worker over pipes; results re-ordered by program id so a campaign is identical whatever the worker scheduling". |
| D-020 | 2026-10-10 | Checker C1 compares status, exit code, registers x1..x31 and the 64 KiB memory hash. | D-025 | 2026-10-11 | The stop rule compares **Q1/n** ("good-turing") with epsilon. Q1/n is the Good-Turing estimate of S31 Eq. 22 and what S32 calls the *coverage rate*: it estimates the expected number of new species in the next program and so upper-bounds the probability that the next program exhibits at least one. It is known to over-estimate (S32), i.e. to err towards running longer, not stopping early. S30's incidence-model formula **Q1/V** (Eq. 29) is reported in every checkpoint row but never used to stop: it answers a different question (the share of species occurrences that are singletons) and is smaller by V/n, the mean number of species per program (about 6.7 in the simulation, see V-32), so as a stop signal it would claim several times less risk than exists. S30's Eq. 28 (`coverage`) is selectable with `stop.estimator`. The dependency-aware estimator of S32 is not implemented; its full text was not read. Early on Q1/n exceeds 1; it is a rate there, not a probability, and the first useful checkpoints are the ones below 1. | Spec section 9 says "read the full source before implementing"; the sources define this quantity differently in the multinomial and incidence models. Resolved by reading S30 Section 7, S31 Section 4 and the S32 abstract, then checking numerically. |
| D-026 | 2026-10-11 | Species. SP-op: instruction kinds retired by the model (41 ids, 38 reachable by the generator). SP-cross: (kind, rs1 class, rs2 class) of every retired instruction, 41 x 8 x 8 = 2,624 ids, where class 0 stands in for an operand the kind does not read; classes in priority order zero, one, minus one, INT_MIN, INT_MAX, small positive (2..255), small negative (-255..-2), other. Each species counts once per program (incidence data). Species come from the reference model's trace of the program, not from the core, and only for programs the model finished. The universe includes cells no program can reach; the estimators work from observed counts and do not use the universe size. SP-cross+, SP-dep and SP-code are later steps. | Spec section 9. Small limit 255 is my choice. |
| D-027 | 2026-10-11 | Stop-rule mechanics: evaluated every `stop.checkpoint` programs (default 1,000); only checkpoints at or after `stop.min_programs` count towards `stop.confirm` consecutive confirmations; the comparison is strict (risk < epsilon); with several species sets the rule uses the maximum risk; `stop.epsilon = 0` switches the rule off (the default, because the real defaults come from the benchmark in Step 11); the program budget is `campaign.programs` and the optional wall-clock budget `stop.max_hours` is checked at checkpoints, across all sessions of a run. The two baselines are recorded for the later compute comparison: the fixed budget, and a plateau rule (first checkpoint where every enabled set had no new species for `stop.plateau_window` programs, `plateau_rule_would_have_stopped_at` in summary.json). | Spec section 9. |
| D-028 | 2026-10-11 | `cutoff run` exit codes (supersedes D-022): 0 stopped at the threshold, or ran every program with the rule off, and no failure; 1 at least one failure (takes precedence over 0 and 2); 2 a budget (programs or hours) ended before the threshold; 3 setup or environment error; 130 interrupted by Ctrl-C or SIGTERM (resumable). | Spec section 5, plus 130 which the spec does not define. |
| D-029 | 2026-10-11 | Checkpoint and resume. `checkpoint.bin` (versioned, FNV-checksummed, written by rename) is saved at every stop checkpoint, on interruption and at the end of every run. It holds a hash of the program-stream settings, the next program id, the byte lengths of `events.bin` and `risk_curve.csv`, the stop-rule state, totals and every tracker's counts. `cutoff run --resume DIR` truncates both files back to those lengths (so output written after the last checkpoint is discarded), deletes failure folders of programs that will be re-run, restores the state and continues; it refuses when the seed, generator, checker limits, species sets or core differ, but accepts a new budget or stop settings, and a finished run can be extended or given a new threshold. `config.toml` is rewritten with the latest session's settings. The orchestrator handles SIGINT and SIGTERM; workers ignore them and are wound down by the orchestrator. | Spec sections 6 and 11: `--resume` must reproduce an uninterrupted run exactly. |
